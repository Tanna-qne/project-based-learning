# DesignBuilder AI 教学插件

状态：已提交 0.1 插件骨架（中文窗口、只读 DB 状态摘要、Dify 聊天接口）；尚未在用户的 Windows + DB 7.3.1.003 环境编译和加载验证。

目标版本：**DesignBuilder 7.3.1.003**（用户已确认）。

快速开始：参见 [WINDOWS_SETUP.md](WINDOWS_SETUP.md)。代码位于 `src/DBAILearningAssistant/`。

## 产品目标

做一个类似 VS Code AI 聊天插件的 DesignBuilder 操作教学助手。插件自动读取当前模型与操作上下文、监听状态变化，结合用户学习目标给出下一步建议；用户也能在聊天窗口追问操作方法和参数含义。用中文逐步指导，保留英文界面名称便于定位。

用户明确要求：核心不是截图识别，不要求上传截图，不替用户点击、修改模型或运行模拟。GitHub 是开发协作中心，不是运行时聊天消息中转站。

## 使用体验与验收标准

- 在 DB 内通过插件入口打开教学聊天窗口；固定侧栏是否支持需先验证，不能提前承诺。
- 输入“我想设置外墙保温，应该怎么操作”，返回适用版本、对象层级、入口、步骤、检查办法和资料来源。
- 支持连续追问，例如“这个选项是什么意思”“我找不到你说的菜单”。
- 当前对象或页面未知时，明确询问；不得假装看到用户界面。
- 优先尝试只读 API 上下文（版本、对象类型、选中对象等）。每项可用性必须通过官方 API 和实际安装验证。API 无法提供的上下文允许用户选择/输入，不偷偷改成截图产品。
- 回答基于与安装版本匹配的官方帮助资料；没有证据时明确表示不确定，不编造按钮或默认数值。
- 不注册模型写入、点击执行或运行模拟能力。

## 实施顺序

1. 已确认 DB 7.3.1.003；检查该安装的插件/脚本入口、匹配 SDK 程序集与许可能力。
2. 从上述官方页面进入官方示例仓库，检查许可证和对应版本插件模板。先验证最小插件能加载、添加入口、打开非模态聊天窗口；使用匹配版本的 DB 程序集和 .NET 目标框架，不能凭空编造接口。
3. 定义只读上下文适配层。逐项记录已证实可读、不可读与待验证的字段。首个技术里程碑必须验证自动上下文读取与事件监听，不能以普通聊天框代替核心需求。
4. 接入问答后端。优先评估用户已有的 Dify 是否继续使用；先核对当前 API 和应用配置。模型及知识库置于后端，GitHub 不承载每次问答。
5. 加入匹配 DB 版本的官方帮助材料和来源引用，验证连续问答、超时、错误提示和缺失上下文处理。
6. 在用户的 Windows + DB 环境实际验证，提供安装、打开和卸载说明。未在 DB 中测试的构建必须标明未验证。

API 密钥不放入仓库、示例配置或日志。实际配置使用本机设置或后端安全配置。仓库是公开的，只保存通用代码、说明和非敏感测试数据。

## 给不同 AI Agent 的工作约定

所有 Agent 开始前阅读本文件，并在任务结束时写明改动、验证结果、阻塞项和下一步。不要假设不同平台共享聊天记忆。

| 顺序 | 角色 | 工作 | 完成证据 |
| --- | --- | --- | --- |
| 1 | 集成调研 Agent | 核对用户版本、官方模板、插件入口、UI 和只读上下文 API | 对应版本的文档/示例链接及可行性记录 |
| 2 | 插件开发 Agent | 最小插件、聊天窗口和上下文适配 | 可复现构建说明；实际 DB 加载结果单独记录 |
| 3 | 问答与资料 Agent | 版本化资料、引用、连续问答和后端接口 | 来源清单与问答样例 |
| 4 | 审查 Agent | 核对安装流程、事实、上下文诚实性和只读边界 | 问题清单及复测结果 |

各 Agent 使用独立分支，通过 PR 交接。先完成接口调研再开展依赖其结果的开发。接入外部 Agent 需要相应账号/运行环境，写下任务不会自动启动它们。

## 7.3 状态读取调研与实现约定

用户要求：像 IDE AI 插件理解项目一样理解 DB 当前模型，监测操作状态，建议下一步；只提供指导。

“代码”分为三类：模型结构/属性是主要上下文；EnergyPlus IN.IDF 是生成时的模拟输入快照，只作补充；DesignBuilder 自身实现源码不是此方案的依赖。读取 IDF 不能告诉我们当前选中了什么，也不能代表尚未重新生成的模型改动。

以下均为官方 7.3 在线文档证据，不是 7.3.1.003 本机验证结果：

| 需要的上下文 | 官方接口线索 | 验证边界 |
| --- | --- | --- |
| 当前模型、层级、对象 | IsActiveProject、CurrentIndices、CurrentObjectType、DecompositionLevel | 当前导航对象不一定等于所有高亮选中对象；关闭模型时清空上下文 |
| 所处工作模式与命令 | ApplicationMode、ViewType、CurrentCommand、GetCommandObject | 不能据此声称知道每个数据页签、输入框焦点或未提交输入 |
| 对象属性与继承 | Site、DataObject 等模型 API | 按官方属性定义逐项映射；区分继承值与显式值、单位、未知值 |
| 对象选择与视图变化 | GlobalEvents 的 ZoneSelected、SurfaceSelected、OpeningSelected、DecompositionLevelChanged、ViewChanged | 在目标安装验证订阅、触发时机与线程约束 |
| Sketch 错误和警告 | ErrorCondition、WarningCondition 与 Errors/Warnings | 不代表覆盖全部 EnergyPlus 模拟错误 |
| 模拟输入 | EnergyPlusInputIdfPath | 文件可能不存在或过期；记录生成时间及关联项目 |

### 首个技术里程碑：只读状态探针

1. 核对官方 7.3 插件宿主模板和该构建所需依赖，确认可获取宿主 Environment 实例；不能自行构造实例并假装连接正在运行的 DB。
2. 插件内显示真实读取的版本、项目是否打开、当前层级/对象索引、工作模式与当前命令；不可用字段明确标为 unknown。
3. 用户依次选择建筑、房间、表面，观察相应事件与状态更新；只记录必要事件，避免记录鼠标移动洪流。
4. 按宿主允许的线程和生命周期读取 API。事件合并后采样；没有属性变更事件的字段，先验证允许的低频读取方式，不能承诺任意参数变化都可即时捕捉。
5. 记录 snapshot_id、observed_at、source、capabilities、missing_fields；项目切换后丢弃旧上下文和旧模型回答。
6. 接 AI 前先人工确认状态与 DB 操作一致。验证通过后将必要的状态摘要、变化及用户目标交给问答后端。

### 建议生成规则

根据“用户目标 + 当前状态 + 已观察到的变化 + 版本匹配帮助资料”生成建议。观察到墙面被选中，不等于知道用户想改善保温；目标未明确时先问。不能将默认参数认定为用户已完成设置，也不能仅凭一次状态推断完整操作历史。

状态监听在本地运行；模型调用做去重与节流，仅在有意义的变化或用户提问时触发。回复附带所依据的状态时间，若用户已切换对象则丢弃或标明旧建议。保留暂停建议功能；不自动点击、写入模型或运行模拟。

验收：不依赖截图；连续切换对象能更新上下文；未知页签不编造；无模型和旧 IDF 可识别；异步旧回复不会误导当前操作；最终建议有明确步骤和依据。
